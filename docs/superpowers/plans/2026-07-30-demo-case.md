# Demo Case Implementation Plan

> **Superseded in part.** The prebuilt `.vestigo` archive this plan is built
> around came out at 146 MiB and was abandoned; the demo case is generated per
> user at seed time instead. The shipped code is `src/vestigo/demo/` (generator)
> plus `src/vestigo/core/demo_case.py` (seeding); `docs/ANOMALY_DETECTION.md`
> and `docs/DEPLOYMENT.md` describe what it actually does. Kept as the
> point-in-time record of the design round.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every user finds a realistic, fabricated demo case in their case list the first time they log in — seeded once per user from a prebuilt `.vestigo` archive, deletable, never auto-restored.

**Architecture:** A generator in `tools/demo_case/` fabricates four log sources plus the analyst artifacts, drives the real ingestion pipeline against a throwaway database, and exports `src/vestigo/assets/demo/demo-case.vestigo` — a committed asset. At runtime, `core/demo_case.py` gates on a setting plus an atomic per-user flag and dispatches a background `JobStore` job that restores the archive through the existing `transfer.importer.import_case()`.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy async, Alembic, ClickHouse, pytest/pytest-asyncio, React 19 + TanStack Query.

**Spec:** `docs/superpowers/specs/2026-07-30-demo-case-design.md`

## Global Constraints

- Ruff: `select = ["E", "F", "I", "UP", "B", "C4", "SIM"]`, `line-length = 100`, `E501` ignored — never wrap a line for length alone. Google-style docstrings.
- Migrations must be dialect-portable: the suite runs them against SQLite. Use `sa.func.now()`, never `sa.text('now()')`.
- Every new `Settings` field needs a matching `SettingSpec` in `core/settings_registry.py` or the registry coverage test fails.
- Nothing may reach the network unconditionally (airgapped-first). The demo archive is a packaged local asset.
- Fixed scenario window: `2026-05-01T00:00:00Z` → `2026-05-30T23:59:59Z`. Baseline days 1–23, suspect days 24–30. No timestamp rebasing at import.
- Detector scope: the 13 non-embedding tools. Semantic similarity (§11) is deliberately excluded — Qdrant vectors are not portable through the archive.
- Demo content carries **no** meta-labels naming detectors. Annotations read as analyst notes.
- Backend commands run from the repo root with `uv run`; frontend commands from `frontend/`.

```python
    async def claim_demo_seed(self, user_id: str) -> bool:
        """Stamp the demo-seed flag, returning True only for the winning caller.

        Conditional on the column still being null, so two simultaneous logins
        cannot both dispatch a seed job. Stamped *before* the import runs: a
        failed import leaves a failed job the user can retry explicitly, which
        is better than re-importing on every login.
        """
        async with self.session_factory() as session:
            result = await session.execute(
                update(User)
                .where(User.id == user_id, User.demo_case_seeded_at.is_(None))
                .values(demo_case_seeded_at=datetime.now(UTC))
            )
            await session.commit()
            return result.rowcount > 0
```

Create `src/vestigo/core/demo_case.py`:

```python
"""Seeding the fabricated demo case into a user's case list.

The demo case ships as a prebuilt ``.vestigo`` archive under
``assets/demo/`` and is restored through the ordinary case-import path, so it
is an ordinary case in every respect once it lands: the user can annotate it,
export it, or delete it, and nothing here treats it specially afterwards.

Seeding is claimed atomically per user (``PostgresStore.claim_demo_seed``) and
runs as a background job, so a login never waits on it and never fails because
of it. The claim is stamped before the import starts: a user whose import fails
sees a failed job and can restore explicitly, which beats retrying the import
on every subsequent login.

The archive is regenerated by ``tools/demo_case/build.py``.
"""

from __future__ import annotations

import asyncio
import logging
from datetime import UTC, datetime
from pathlib import Path

from vestigo.core.config import get_settings
from vestigo.core.jobs import get_job_store
from vestigo.db.clickhouse import ClickHouseStore
from vestigo.db.postgres import User
from vestigo.transfer.importer import import_case

logger = logging.getLogger(__name__)

JOB_KIND = "demo_seed"

#: Background seed tasks, kept referenced so the event loop cannot collect a
#: running task mid-import (asyncio holds only weak references).
_pending: set[asyncio.Task] = set()


def demo_archive_path() -> Path:
    """Absolute path to the packaged demo archive (may not exist in a dev tree)."""
    return Path(__file__).resolve().parent.parent / "assets" / "demo" / "demo-case.vestigo"


async def maybe_seed_demo_case(user: User) -> str | None:
    """Seed the demo case for ``user`` if they have never been seeded.

    Returns the background job's id, or None when seeding is disabled, the
    archive is absent, or this user already had their turn. Never raises: a
    login must not fail because of the demo case.
    """
    settings = get_settings()
    if not settings.demo_case_enabled:
        return None
    if not demo_archive_path().is_file():
        logger.debug("demo seeding skipped: archive missing at %s", demo_archive_path())
        return None
    try:
        from vestigo.api.deps import get_store

        if not await get_store().claim_demo_seed(user.id):
            return None
        return _dispatch(user)
    except Exception:  # noqa: BLE001 — seeding must never break a login
        logger.exception("demo seeding failed to start for user %s", user.id)
        return None


async def seed_demo_case(user: User) -> str:
    """Seed unconditionally (the explicit 'restore demo case' action).

    Raises FileNotFoundError when the archive is absent; the caller turns that
    into an HTTP error.
    """
    if not demo_archive_path().is_file():
        raise FileNotFoundError("demo archive is not packaged with this build")
    from vestigo.api.deps import get_store

    await get_store().claim_demo_seed(user.id)  # best-effort stamp; already-set is fine
    return _dispatch(user)


def _dispatch(user: User) -> str:
    job = get_job_store().create(
        kind=JOB_KIND,
        progress={"phase": "queued", "processed": 0, "total": None},
        created_by=user.id,
    )
    task = asyncio.create_task(_run_seed_job(job.id, user))
    _pending.add(task)
    task.add_done_callback(_pending.discard)
    return job.id


async def _run_seed_job(job_id: str, user: User) -> None:
    from vestigo.api.deps import get_store

    jobs = get_job_store()
    jobs.update(job_id, status="running")
    store = get_store()
    try:
        result = await import_case(
            store,
            ClickHouseStore,
            demo_archive_path(),
            owner=user,
            job_id=job_id,
            progress=lambda p: jobs.update(job_id, progress=p),
        )
        await store.record_audit(
            action="case.demo_seeded",
            actor=user,
            case_id=result.case_id,
            target_type="case",
            target_id=result.case_id,
            detail={"job_id": job_id, "counts": result.counts, "at": datetime.now(UTC).isoformat()},
        )
        jobs.update(
            job_id,
            status="completed",
            result={"case_id": result.case_id, "counts": result.counts},
        )
    except Exception as exc:  # noqa: BLE001 — job error surface
        logger.exception("demo seed job %s failed", job_id)
        jobs.update(job_id, status="failed", error=str(exc))


async def _await_pending_seeds() -> None:
    """Await in-flight seed tasks. Test helper — not used by the app."""
    while _pending:
        await asyncio.gather(*tuple(_pending), return_exceptions=True)
```

```python
here is fixed. The archive must be byte-reproducible from a clean checkout, so

shared generator: adding or reordering a source then cannot shift the output of
every other source, which keeps regeneration diffs readable.

Scenario: the contractor account m.okonkwo is sprayed from a VPN pool, gains a

from collections.abc import Iterator
from dataclasses import dataclass
from datetime import UTC, datetime, timedelta

SCENARIO_START = datetime(2026, 5, 1, tzinfo=UTC)
SCENARIO_END = datetime(2026, 5, 30, 23, 59, 59, tzinfo=UTC)

    "f.haddad", "g.petrov", "h.ivanova", "m.okonkwo", "svc_backup", "svc_scan",
)

JUMP_HOST = "JUMP-01"

def rng(stream: str) -> random.Random:
    """A reproducible generator for one named stream."""
    return random.Random(f"{_SEED}:{stream}")


def walk(start: datetime, end: datetime, per_day: int, r: random.Random) -> Iterator[datetime]:
    """Yield sorted timestamps at roughly ``per_day`` per day, weighted to work hours.

    Weekends get about a fifth of the volume and the hour-of-day weights peak
    mid-morning and mid-afternoon: without this, every frequency and cadence
    detector sees a flat synthetic baseline and the demo looks fake at a glance.
    """
    hour_weights = [1, 1, 1, 1, 1, 2, 4, 9, 18, 24, 26, 22, 18, 22, 26, 24, 18, 11, 7, 5, 4, 3, 2, 1]
    stamps: list[datetime] = []
    day = start
    while day < end:
        weekend = day.weekday() >= 5
        count = max(1, int(r.gauss(per_day * (0.2 if weekend else 1.0), per_day * 0.12)))
        for _ in range(count):
            hour = r.choices(range(24), weights=hour_weights, k=1)[0]
            moment = day + timedelta(hours=hour, minutes=r.randrange(60), seconds=r.randrange(60))
            if start <= moment < end:
                stamps.append(moment)
        day += timedelta(days=1)
    yield from sorted(stamps)
```
